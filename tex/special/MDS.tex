Multi-dimensional scaling (MDS) is a kind of dimensionality reduction, allowing one to translate a set of items and their predetermined pairwise distances into an arrangement of points in Cartesian space, typically in two dimensions. This is not a trivial task. Consider the meme below, which references social distancing guidance from the coronavirus pandemic. We have four individuals, forming six possible pairs, and any two individuals must maintain a six-foot distance. The graphic shows impossible right triangles that violate the Pythagorean Theorem when the distances are all exactly six feet. Indeed, there is no way to arrange four individuals in two-dimensional space so that they are all exactly six feet apart. This highlights one difficulty in multi-dimensional scaling---we must accept some error in our output.

The following diagram helps show why no alternative arrangement could be perfect. Each point $a,b,c$ is in the middle of a circle of six-foot radius. For $b$ to be six feet away from $a$, $b$ must lie on the circle centered at $a$. Similarly, for $b$ to be six feet away from $c$, $b$ must also lie on the circle centered at $c$. For three points, this arrangement is possible. But if we introduce $d$, $d$ must lie on all three of the circles centered at $a$, $b$, and $c$. But there is no point where all three circles intersect.

\section{From Dissimilarities to a Map}

We can give that impossible request directly to MDS. The matrix below has zeros on the diagonal because each item is identical to itself and ones everywhere else because every distinct pair has a target dissimilarity of one. The matrix is symmetric: the dissimilarity from $a$ to $b$ is the same as the dissimilarity from $b$ to $a$.

The code passes the matrix to scikit-learn's \link{https://scikit-learn.org/stable/modules/generated/sklearn.manifold.MDS.html}{\code{MDS}} estimator with \code{dissimilarity = 'precomputed'}. The \code{n\_components} argument requests two output dimensions. MDS begins from an initial arrangement and repeatedly moves the points to improve the fit. We set \code{random\_state} so the example can be reproduced and use several initial arrangements with \code{n\_init}; the estimator keeps the one with the lowest stress.

The result is approximately a square. That is a compromise, not a discovery about the four people. The four sides are about $0.85$ units long while the two diagonals are about $1.21$ units long. MDS makes some pairs too close and others too far away because a perfect two-dimensional arrangement does not exist.

The estimator summarizes this mismatch with \emph{stress}. For metric MDS, raw stress is the sum of squared differences between the target dissimilarities $\delta_{ij}$ and the fitted distances $d_{ij}$:

\begin{equation*}
    \text{stress} = \sum_{i < j}\left(\delta_{ij} - d_{ij}\right)^2.
\end{equation*}

A perfect fit has zero stress. Lower values indicate a better fit, but raw stress has no universal ``good'' cutoff: it changes with the number of items, the scale of the dissimilarities, and the requested number of dimensions. Compare it only across models fitted to the same dissimilarity data under the same convention. Adding a third dimension would allow this particular example to form a regular tetrahedron with zero stress, although a three-dimensional chart would be harder to read on the page.

\section{Reading an MDS Map}

The distances are the meaningful part of an MDS map. The horizontal and vertical axes ordinarily have no substantive interpretation. The entire configuration can be translated, rotated, or reflected without changing any pairwise distance, so a second valid fit might appear in a different location or orientation. A fixed \code{random\_state} makes a published example repeatable, but it does not turn either axis into a measured variable.

The input deserves as much attention as the output. State what the dissimilarities mean, how they were calculated, and whether large values represent greater difference. Then inspect stress and, for a substantive application, compare the fitted distances with the original dissimilarities. A polished scatter plot cannot rescue an inappropriate distance measure or a badly distorted two-dimensional solution.

\section{How MDS Differs from PCA}

Principal component analysis (PCA) is a useful comparison, but it solves a different problem. PCA starts from a rectangular table of observations and measured features, then finds linear combinations of those features that capture as much variance as possible. Its axes can be investigated through the feature loadings. MDS can instead begin with only a square dissimilarity matrix, making it useful when the relationships are meaningful but the items do not have a natural set of numeric features. Its axes are generally left unlabeled because proximity, not direction, is the object of interest.

There is a mathematical bridge between the two methods. When the input contains Euclidean distances calculated from a feature matrix, classical MDS is equivalent to PCA on the centered feature data. That connection is worth knowing, but it does not make the iterative metric MDS fit above a PCA plot, and it does not give the plotted axes substantive meanings. For an introduction to PCA itself, see scikit-learn's \link{https://scikit-learn.org/stable/modules/decomposition.html\#principal-component-analysis-pca}{PCA guide}; a full PCA treatment belongs in a dimensionality-reduction chapter rather than in this plotting example.

MDS is most persuasive when readers understand the dissimilarities, see the important proximities, and know how much fidelity was lost. The algorithm supplies coordinates; the storyteller must explain what closeness means and where the map distorts it.
